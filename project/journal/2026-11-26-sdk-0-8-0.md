# SDK 0.8.0, and the Blender targets name the SDK's lib (opus-blend132, meta QA 11-25 row 132)

- `pnpm dlx @wildshard/cli upgrade 0.8.0`: the SDK, cli, dev and kit at 0.8.0, format 0.80.0 (engine 0.1.96). Driftwood
  names no `legacySlot`, so the migration had no manual step. The hero re-stamped its content hash; the curated art is
  unchanged.
- `scripts/blender/targets.json` named the SDK's export step as `scripts/blender/lib/export-scene.mjs`, a monorepo
  path. The `pre` command now runs `$SDK/scripts/blender/lib/export-scene.mjs` (build.sh expands `$SDK`), and the file
  lists name it by its installed path, `node_modules/@wildshard/sdk/...`, as they do the arm rig (`armRig.ts`).
- Two inputs live in other repos: the CC0 palms and rocks (`driftwood-cc0/`, in shard-pine-hollow) and Nine Dragon's
  rig (`fp-rig.glb`, in shard-nine-dragon). Each target lists them under `external`, with the repo, so
  `check-model-sources.mjs` passes on what this repo holds.
- The manifest still sits at `scripts/blender/`: the installed engine 0.1.96 lint finds the registered Blender helpers
  only there. Its move to `src/blender/` waits on an SDK publish that pins an engine with `6488b9233` (v0.1.97).
