# Driftwood's own paths for sdk 0.5.0

> Written by: Claude (opus, session 015pj4Rw), 2026-11-25

SDK 0.5.0 (sharddev plan `opus-2026-11-24-sdk-migrate-static`, row R2)
moves a shard repo's `public/` into `src/static/` and builds into
`out/<slug>`. Jake: "I'd rather have all the source code of the game
zone be in ./src/ and the generated shardfile output in ./out/ and
remove the ./public/ directory", and "just the move without the rename",
so every name inside the shard stays the same and the product is
byte-identical.

`wildshard upgrade 0.5.0` does the move itself. This commit is the
part it lists as manual: the places in this repo that name the old
paths.

- `scripts/ci21-source-product.mjs` and `test/fixtures/builtProduct.ts`
  sealed `src/` plus `public/` and allowed two kinds of copies there
  (publish-public's `src/assets/public/` aliases and the builder's map
  `top.webp`). Neither exists on 0.5.0, so the sealed inputs are exactly
  the tracked `src/` tree. The control test now proves a static mount
  is an ordinary sealed input instead of proving the aliases.
- `scripts/blender/targets.json`, three fixtures, three tests and
  `docs/design.md`: `public/assets/` is `src/static/assets/`.
- Not here: `publish.yml`, `scripts/publish-shard.mjs` and
  `scripts/keep-copy.mjs` are kit-owned; their `public/` mentions are
  fixed in repo-kit for every shard repo.

## The upgrade itself

`pnpm dlx @wildshard/cli@0.5.0 upgrade 0.5.0` (0.4.31's own CLI has no
`upgrade`). It moved the pins, then the 0.5.0 migration moved 162
files from `public/` and `src/assets/public/` into `src/static/`,
removed `public/`, dropped `publish-public.mjs` and synced GUIDE.md, the
skills and the status hook. Its check passed.

Product: a fresh 0.4.31 baseline from this branch, rebased on main, and
the 0.5.0 build agree on 562 of 563 files. Only `validation.json`
differs, because its build key names the sdk. No `public/` came back.

Left for us after it:

- Five test reads written as `` `public${url}` ``. A `public/` grep
  misses that form, and so did the migration's manual-step scan. They
  read `src/static${url}` now.
- `check:agent-sync` failed: the new `.agents/hooks.local.json` was
  never synced into `.claude/settings.json` and `.codex/hooks.json`.
  Ran `node scripts/agent-sync.mjs`. Told the release owner so the roll
  runs it too.
- `package.json` `engines.node`: the upgrade dropped the repo's `<25`
  bound, and the Node 24 guard refused the commit. Restored by hand.
- `src/hero.json`: the source hash moved and the art didn't, so the
  hero was re-stamped and not recaptured.

Left alone: the `public/` strings in `mapProgram.ts` and
`mapAssembly.mjs` are names in the map producer's input bank, not
paths, and renaming them is out of scope. The old bake and Blender
scripts that resolve outside this repo are leftovers from the import.

## ci21-source after the land

Main's first ci on 0.5.0 (76b683f) went red in ci21-source:
`scripts/assert-candidate-engine.mjs` matched the sdk pin against
`0.4.\d+`. It now takes any exact version, so the next minor doesn't
trip it either.
